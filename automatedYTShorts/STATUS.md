Roadmap called for: faster-whisper (already in place since Milestone 4), GPU acceleration if available, cache transcripts (already in place since Milestone 17's resumability work - transcribe() has skipped re-transcribing when transcript.json exists since then), avoid re-rendering unchanged clips (already in place - every ffmpeg stage skips a clip whose output file already exists), process clips efficiently, and clean temporary files automatically. Did the three that weren't already done:
1) GPU: transcriber.py's new _transcribe_audio() checks ctranslate2.get_cuda_device_count() and tries device="cuda"/compute_type="float16" first, falling back to CPU/int8 on ANY exception - not just when no GPU is detected. Real-world reason this matters: on this exact machine, ctranslate2 reports a CUDA device (driver is installed) but WhisperModel actually fails at inference time with "Library cublas64_12.dll is not found" (the full CUDA toolkit isn't installed, only the driver) - detection alone would have crashed the whole transcription stage; the fallback catches it and completes on CPU instead.
2) Efficiency: added run_in_parallel() to app/utils.py (a small ThreadPoolExecutor wrapper - ffmpeg subprocesses block their own thread rather than holding the GIL, so this gives real wall-clock speedup) and used it in clipper.py, vertical.py, and captions.py to cut/convert/caption all of a video's clips concurrently instead of one ffmpeg process at a time. Deliberately did NOT parallelize quality_control.py - it mutates a shared hash-registry file (logs/clip_hashes.json) per clip via read-modify-write, and parallelizing that would introduce a lost-update race between threads.
3) Cleanup: new app/cleanup.py deletes disposable intermediates once their downstream artifact exists - work/<id>/audio.wav once transcript.json exists (audio is never read again after that), output/<id>/clip_NN_raw.mp4 once clip_NN_vertical.mp4 exists, and clip_NN_vertical.mp4 once clip_NN_captioned.mp4 exists BUT ONLY when captions are enabled (with captions disabled, vertical.mp4 is the actual final deliverable and must be kept). Gated by new config.json cleanup.delete_intermediate_files (default true). Wired into main.py's process_url() right after the transcribe and add_captions stages. Nothing this deletes is unrecoverable - source.mp4 is never touched, so worst case a deleted intermediate just costs a re-encode from source.mp4 again.

--- MILESTONE HISTORY (most recent first) ---

Milestone 7 (vertical 9:16 format): app/vertical.py. Initial version did a plain center-crop, which visibly cut off speakers' faces on both test videos. Upgraded to face-detection-based cropping (OpenCV Haar cascades, frontal->profile->flipped-profile fallback, area-weighted average position across 16 sampled frames per clip). Along the way, fixed a real bug where a fixed minSize=(60,60) was far too permissive on 4K source video and matched noise as faces - minSize now scales with the frame's own dimensions. Requires opencv-python-headless<5 (v5 removed the Haar cascade API in favor of a DNN detector needing a separate model download).

Milestone 6 (clip cutting): app/clipper.py. Cuts each candidate out of source.mp4 via ffmpeg accurate seek + re-encode (libx264 crf20 + aac). Frame-accuracy verified by comparing extracted frames between a raw clip and the source at the corresponding absolute timestamp.

Milestone 5 (clip selection): app/clip_finder.py + app/config.py. Rule-based candidate selection directly on raw transcript segments (not merged into blocks - Whisper's segments here are already granular). Builds 20-60s windows ending at natural segment boundaries, avoiding internal silences >3s, scored by closeness to target duration + word count, greedily deduped by overlap. Independently stress-tested with synthetic transcripts (silence-spanning, empty input, over-long single segment, over-requesting clips all handled correctly).

Milestone 4 (transcription): app/transcriber.py using faster-whisper (model_size="base", CPU, int8). Produces transcript.json/transcript.txt. Noted early that this model's segments are choppy phrase fragments, not full sentences - this shaped how clip_finder.py and captions.py were designed.

Milestones 1-3 (setup, download, audio extraction): Python/FFmpeg/Git verified, venv + project structure created. app/downloader.py (yt_dlp Python API) and app/audio_extractor.py (ffmpeg mono 16kHz WAV) built and tested against multiple real YouTube videos. FFmpeg needed manual winget install (Gyan.FFmpeg) since it wasn't preinstalled; app/utils.py's find_executable() falls back to the winget install path when ffmpeg/ffprobe aren't on PATH (a recurring necessity across every stage that shells out to ffmpeg).
